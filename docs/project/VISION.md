# Product vision

Proactive Agent starts as Hermes Agent and evolves into a personal harness that understands ongoing work, follows through, and feels good to use. Hermes is the foundation, not a disposable prototype.

## Product outcomes

- A new user can configure a provider, understand available capabilities, and complete a useful first task with actionable errors along the way.
- A returning user can continue a goal without re-explaining preferences, decisions, and current state.
- The agent can move authorized work forward when relevant events occur, with understandable controls over interruptions, spending, and actions.
- Users can inspect what the agent remembers, where it came from, and why a proactive action happened.

## Principles

**Polish is behavior.** Loading, streaming, interruptions, recovery, and task completion matter as much as appearance. Improve the existing interaction surfaces based on real flows before choosing a new UI.

**Capability should be reachable.** Inventory Hermes's features and configuration first. Prefer surfacing an existing capability over adding another implementation.

**Best context means the right context.** Prioritize accurate, relevant, current information. Maintain a small stable instruction layer, retrieve task-specific evidence, and compact completed work without losing decisions or unresolved obligations.

**Proactivity follows intent.** Support persistent goals and bounded follow-through. Authority, budgets, pause/cancel controls, and notification preferences must be understandable. Start with one user-enabled workflow before generalizing.

**Progress should be measurable.** Use repeatable tasks and synthetic fixtures to compare completion, context relevance, cost, latency, unnecessary interruptions, and recovery after a restart.

## Deliberately undecided

Final branding, the primary interaction surface, hosting model, default model/provider, and the first real-world proactive workflow remain product choices. Do not imply they have been selected. Initial engineering should leave these choices open without speculative abstractions.
