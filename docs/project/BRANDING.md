# Branding and compatibility

The product is **Tandem Agent** (short: **Tandem**); the terminal command is `tandem`. It is built on
[Tandem Agent](https://github.com/NousResearch/hermes-agent) by Nous Research (MIT, see [UPSTREAM.md](UPSTREAM.md)).
This page records what the rename changed and what it intentionally left alone. The earlier interim names
were "Tandem Agent" (upstream) and "Tandem Agent" (project working title).

## Rules for new text

- User-facing copy (CLI, TUI, dashboard, desktop, gateway replies, docs, skills, prompts) says Tandem. Do not
  write "Tandem" for the product; write it only for upstream attribution or the Nous Hermes model family.
- Show `tandem …` in commands and hints. `tandem` keeps working as an alias, so never remove it.
- Do not rename a stable identifier in a copy edit. The table below needs a designed, tested migration first.

## Intentionally unchanged (compatibility)

| Identifier | Why it stays |
| --- | --- |
| `tandem` command, `hermes-agent` / `hermes-acp` entry points | Alias for existing scripts, service units, editor integrations |
| Package/distribution name `hermes-agent`, Python modules (`hermes_cli`, `hermes_state*`, …), npm package names | Imports and lockfiles; upstream merges |
| `~/.hermes`, `HERMES_HOME`, `HERMES_*` environment variables, profile directories | Existing user data and config; no copy or move is performed |
| Config keys, tool/skill/toolset names, `metadata.hermes` skill frontmatter, `X-Hermes-*` headers | Stored config and wire contracts |
| systemd/launchd/Task Scheduler service names (`hermes-gateway`, `ai.hermes.*`) | Reinstall/uninstall must find existing services; only descriptions changed |
| Desktop packaging identity: `productName`/`name` in `apps/desktop/package.json`, `appId` `com.nousresearch.hermes`, executable/bundle names, MSIX identity, Electron `userData` folder (`Tandem`), keychain identity `Hermes Local Signing` | Renaming moves user data, breaks the updater feed and macOS permission grants; needs a signed build to verify |
| Windows Store/appx tiles, bootstrap-installer icons, `nous-girl-*` artwork | Generated by the upstream icon pipeline from Nous artwork |
| `plugin-catalog/` entries and `requires_hermes` | Third-party plugin metadata; descriptions are maintainer-authored |
| Release notes, `RELEASE_v*.md`, `website/blog/` | Historical record |
| `LICENSE`, `UPSTREAM.json`, `UPSTREAM.md`, `SECURITY*.md` contacts, skill `author:` credits, upstream docs URLs | Attribution and third-party facts |
| GitHub repository `robosalvy1/proactive-agent` | Remote repository rename is a separate owner action |

## Migrations performed

- **Default persona.** `DEFAULT_SOUL_MD` and the built-in identity prompt now say "Tandem Agent". A `SOUL.md`
  that still holds an unedited earlier default or scaffold (Tandem, Proactive, or Tandem spelling) is upgraded
  in place by the existing legacy-template mechanism (`hermes_cli/default_soul.py`); any customised file is left
  untouched.
- **Agent name.** The onboarding `AGENT_NAME.txt` and any custom skin `agent_name` still win; only the built-in
  fallback changed.
- **Version output.** `tandem --version`, the banner, `/version` and ACP report `Tandem Agent v…`. Code that
  recognised the old banner (the relay stock-brand check, Claude OAuth prompt sanitiser, kanban log filter,
  contributor audit, skill linter) accepts both names.
- **Anything stored by a user** (config, memories, sessions, skins, `.env`, cron jobs) is not rewritten.
