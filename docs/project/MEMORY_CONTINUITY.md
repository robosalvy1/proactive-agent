# Memory continuity

Home keeps its existing small native notes, transcript store, optional external provider and stable prompt prefixes. This change adds optional semantic retrieval, explicit private-conversation grants and source controls. It does not enable a provider or alter a personal profile.

## Semantic retrieval

Keyword recall works without configuration or network access. To add semantic retrieval, configure an OpenAI-compatible embedding endpoint in the owning profile:

```yaml
memory:
  home_recall:
    enabled: true
    auto_index: true          # optional: embed new messages after each turn
    base_url: https://your-embedding-provider.example/v1
    model: your-embedding-model
    api_key_env: HOME_EMBEDDING_API_KEY
    timeout_seconds: 5
    min_similarity: 0.55
```

Set the default credential through `hermes config set HOME_EMBEDDING_API_KEY` or the profile's secret environment, not YAML. A custom `api_key_env` can reference another existing profile secret. HTTPS is required except for loopback HTTP. Local endpoints can omit a credential. No chat-provider credential is silently borrowed. Changing endpoint or model selects a new embedding space.

Open `/home`. Automatic indexing is a separate opt-in: with `memory.home_recall.auto_index: true`, indexing runs after each completed turn on the existing background memory-sync worker (managed-worker turns are indexed by their owner). Without it, indexing runs only on `/home index`; enabling semantic recall alone never uploads history after turns. Each step scans at most 256 message rows and sends at most 32 excerpts/16,000 characters in one request, newest messages first, then backfills older history. The batch budget accounts for redaction expansion before dispatch. A single source still over budget is skipped and reported so later sources can advance. Automatic and explicit steps share a short database lease, so concurrent processes never upload the same batch, and they fail open: an unavailable endpoint leaves keyword recall and the chat unaffected. After a transport failure (timeout, refused or dropped connection) the endpoint backs off for 15 seconds, doubling to 10 minutes, and both indexing and query embedding skip it without a request, so a hung provider costs at most one timeout per window rather than one per turn. `/home index` retries immediately, drains for up to 20 seconds, first re-verifying a completed pass (reusing unchanged vectors, refreshing edits), and reports the remaining older history. `/home index status` shows the vector count, remaining backfill and endpoint health. Profiles that opt into neither `auto_index` nor `observe` attach the read-only provider and schedule no background work; with `observe` on, the post-turn step also sends settled conversation text to the `home_dream` route (see below), even without semantic recall. No daemon, model download or recurring job is installed; owner-mediated workers have no database access, so their owner's later steps reach those rows.

The index holds at most 50,000 source vectors and 64 MiB of vector data (about 43,700 sources at 384 dimensions, 5,460 at 3,072). Each vector also stores one sign bit per dimension; large indexes rank every sign code by Hamming distance and rescore only the closest candidates (at least 256, growing with the index) by exact cosine, so the threshold always applies to exact scores. When candidates are lost (deleted, excluded, from the current chat, or of a different dimension), the next-closest round is rescored, up to eight rounds. A provider that changes dimensions under the same model rebuilds that index. Indexes built before sign codes use the exact scan until steps backfill them. When it is full, new sources replace the oldest vectors and backfill pauses, so recent history stays searchable; older history remains keyword-searchable. Backfill resumes when forgetting or exclusion frees space, and sharing an older chat or linking a conversation restarts coverage (unchanged vectors are reused). Each step also sweeps a bounded slice of stored vectors, dropping those whose source was deleted, forgotten, or excluded from this principal's Home; sources owned by other principals are left alone. Edited sources in the slice are re-embedded; their stale vectors are never served because recall rechecks the source hash. A superseded original stays indexed so recall can follow it to its correction. Source excerpts are capped at 900 characters. `/home index clear` clears derived vectors and indexing cursors, and revokes publication by an in-flight indexing request; it preserves history and source controls. Recall makes at most one query-embedding request and combines semantic and keyword results by reciprocal rank. It keeps Home's eight-excerpt/6,000-character context cap. Invalid responses, unavailable endpoints and optional query failures retain keyword recall. The embedding model and similarity threshold determine relevance; the runtime cannot guarantee semantic accuracy.

Derived vectors live in the existing profile SQLite database. Every result must still match canonical content and current participation. Deletion, edits, exclusion, forgetting and access revocation are rechecked before use. Provider I/O runs outside read transactions; managed workers validate their assignment before and after it. Inputs are redacted in the database owner's profile before egress. Vectors are derived sensitive data: excluding a source prevents retrieval, but is not secure deletion of database pages or backups.

## Observations and profile (experimental, opt-in)

With `memory.home_recall.observe: true`, the background memory-sync worker also sends settled conversation text to the auxiliary model on the existing `home_dream` route (`auxiliary.home_dream`) and stores dated, self-contained observations about the user in the profile database (`home_observations`). Several due chats share one bounded request (24,000 characters, at most 40 observations); an active chat is observed after eight new messages or ten idle minutes. Observer and profile requests share one lease and a budget of 48 requests per day; provider outages never skip evidence, and a malformed response retried three times narrows a multi-chat batch to one chat before only that chat's batch is skipped; each reservation sends exactly one provider request (no retry or fallback ladder), and consent is rechecked before every automatic request and before anything is published. Inputs are redacted, and configuration, redaction and dispatch all run in the database owner's profile scope. A malformed or refused response consumes nothing; the batch is retried later.

Each observation cites the canonical messages it came from. Facts, preferences, events, plans and updates must cite a user message, and assistant notes are always stored as "The assistant said: …", so assistant or tool text is never recorded as a fact about the user. This reduces memory poisoning but does not eliminate it: text the user pastes or quotes into their own message still counts as theirs. Every read revalidates each cited source: it must still exist, be unsuppressed and be in this principal's Home.

A reflector folds new observations into a bounded profile (people, health and constraints, upcoming commitments, goals, current facts, preferences, lessons), in pages of at most 40,000 characters. The profile records which observations it was built from and is injected only if all of them still validate, so forgetting, superseding, excluding, deleting, hiding or editing a source (or the user message an assistant reply answers) withdraws it immediately; each citation stores a fingerprint of the exact text the observer read; it is rebuilt from the remaining observations. It is read once when a local session's system prompt is built, so prompt caching is unaffected, and it is labelled as fallible, model-written memory that is never an instruction and that the user's current words override. Turning `observe` off stops both observation and injection.

With `observe` on (and unless `memory.home_recall.connect: false`), each local turn in a chat that takes part in Home (messages of 12 characters or more) also sends the current session block, up to 30,000 characters of the user's validated observations, and the user's message, all redacted in the owner's profile scope, to the same auxiliary route in one bounded request (12-second timeout, no retries) that lists the remembered facts that should change this answer, including ones the user did not mention (who an indirect description refers to, birthdays, conflicting commitments, constraints, goals, past outcomes). The result is appended to that turn's Home recall context as fallible notes, never instructions; on any failure the turn continues without it. This adds one auxiliary request per turn (median 3.3 s, p90 5.7 s with GPT-5.6 Luna over the Codex route in our eval); reading all observations rather than only the profile, it raised proactive recall from 70% to 83% across 138 evaluation scenarios in five sets, including two generated after the design was fixed. Set `connect: false` to keep the profile without the per-turn request. The model behind `auxiliary.home_dream` matters: on a fresh 27-scenario set the per-turn check reached 78% with GPT-6 Sol, 74% with GPT-5.6 Luna and 67% with GPT-6 Luna (median 4.8 s, 4.4 s and 2.6 s per request); a strong model is recommended. With GPT-6 Sol on the whole route (observer, reflector and check), two fresh sets reached 89% and 96% (93% of 54 scenarios), against about 22% for Home excerpts. Each principal has its own cursors and profile. Observations are drawn from every chat in this principal's Home, including messaging chats the owner explicitly linked from a local session; linked messaging chats and managed workers do not receive the profile or per-turn connections yet.

## Private messaging

From a local personal chat, use `/home link <session-id>` to grant an existing private messaging conversation access to Home. `/home links` lists grants; `/home unlink <session-id>` revokes one. Find the session ID through the existing session list/history controls. No messaging conversation participates merely because it shares a username or numeric sender ID with another app.

A grant binds the exact persisted platform, sender, chat, thread, receiving-bot profile, session key and routing scope. The current gateway source must match. Groups, broadcasts, unknown identities, jobs and subagents are excluded. Compression may preserve a grant when its identity is unchanged; a new/reset conversation requires relinking. Profile and local-owner authorization still apply. Grants enable source retrieval as well as replies using Home context; they do not authorize external actions.

## Corrections and forgetting

Home evidence exposes canonical message IDs. Local controls are:

```text
/home supersede <old-message-id> <new-user-message-id>
/home forget <message-id>
/home sources
```

Controls on a user message also govern every assistant message that answers it (each assistant message answers the latest user message before it in its chat). This is enforced on every read, so a forgotten fact is not served through the assistant's restatement however long the tool loop was, even for replies written after forgetting, and a correction wins over it. An assistant message's own control takes precedence. A user message queued before the previous turn's final answer is persisted can shift that association. Supersession follows a newer explicit user correction, even if its wording no longer matches the original query. It never substitutes an assistant suggestion as a user fact. Forgetting suppresses the stable source identity, including compression copies, across keyword recall, semantic recall and dream processing. Revocation survives restart and physical message deletion. An unavailable/excluded replacement does not restore its original. Source controls are capped at 10,000; existing controls are never evicted to admit another.

These controls affect future Home retrieval. They do not erase raw transcripts, every independently written paraphrase, native `MEMORY.md`/`USER.md`, external providers, exports or backups. Start a new chat to remove previously loaded context; resuming an old chat retains its old prompt bytes. Native/external memory deletion uses its own controls. This source-level feature does not claim general learned-fact erasure or automatic contradiction detection.

## Learning and compression

Automatic memory/skill review defaults off. An explicit `auxiliary.background_review.enabled: true` preserves opt-in; `/refine` and foreground memory saves remain available. The reviewer may do nothing when there is no durable, supported lesson. Home dreaming remains a separate opt-in with its existing budgets and source gates.

Compression retains its existing transcript persistence and provider-checkpoint hooks. There is no new unattended native-fact extraction call: its quality and cost have not been established. Explicit saves remain the way to curate small always-loaded notes; source-backed Home recall supplies detailed history.

## Evaluation boundary

The regression suite uses synthetic conversations, local HTTP servers and controlled vectors. It covers paraphrase retrieval versus the keyword baseline, distractors, exact matches, correction and revocation, profile/identity isolation, restart, provider errors and prompt-prefix preservation. Controlled vectors verify retrieval mechanics, not a real embedding model's understanding. Live embedding quality, end-to-end answer quality and monetary cost require a disposable configured provider evaluation before choosing defaults or enabling broader automation. No comparison here establishes universal superiority over OpenClaw.
